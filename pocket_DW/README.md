# Pocket Digimon World · DigiKidult 繁體中文攻略

可直接放上 GitHub Pages 的獨立靜態網站。視覺參考現有 DigiKidult Ver.WS 頁面：深藍、米白及淺綠配色、卡片式資料、品牌底欄。內容為 Pocket Digimon World，不沿用 WonderSwan 的遊戲數值。

## 預覽

解壓後直接開啟 `index.html`。搜尋、篩選、翻譯及圖像查看均不需要網絡，亦不需要安裝套件。

包括：

- 四版本172個進化條件方法，合併為130組「來源→目標」，可按版本、來源／目標及條件搜尋。
- 由成長期開始排列，按「下一步」接續查找；相同配對的共同條件只列一次，各方法並列比較。
- 119筆招式資料及最低智力。
- 培育、對話影響、日曆觸發、時段記錄及原版Fire管理提示。
- 新手教學：每日怎樣玩、第一次進化、下一階段規劃、進化失敗排查。
- 30張中文對話卡：完整問題、所有回答及影響放在一起，問題及每個答案均直接配上對應日文原文。
- 79份角色圖像總覽，可放大查看。
- 445筆日曆文字、建議對話及選項翻譯。

## 放上新的 GitHub Pages

1. 建立或選擇用於這份攻略的儲存庫。
2. 將本資料夾**內的全部內容**放到發布根目錄，包括 `index.html`、`style.css`、`app.js`、`data.js`、`.nojekyll` 及整個 `assets/`。
3. 在儲存庫的 Settings → Pages 選擇分支發布，指定實際上載的分支（例如 `main`）及根目錄 `/ (root)`。
4. 等待 GitHub 顯示發布完成，使用 Pages 提供的網址檢查頁面。

若現有儲存庫已設置 Actions 或其他發布來源，沿用該儲存庫的實際設定；本包不包含需要執行的建置流程。

## 加入已有的網站

可把本資料夾內容整份放到例如 `pocket-digimon-world/` 子目錄，再從原有網站連到 `./pocket-digimon-world/`。所有網站資源使用相對路徑，支援 GitHub 專案頁及子目錄。

這是另一款遊戲的獨立頁面，**不要用本包覆蓋現有 Ver.WS 網站根目錄**，除非你確實要取代該網站。本次沒有改動 Ver.WS 原檔，也沒有推送或發布到 GitHub。

## PS1 AI、傷害及戰後增幅整合

新增 `index.html#combat-guide`，以玩家角度說明選招、MP不足、先手、迴避、傷害、屬性取整及練功收益；另附普通命中試算。必須一併更新 `combat-data.js`、`combat-guide.js` 及 `style.css`。這是三張PS1光碟的判定，不套用到PocketStation。

普通出招計算：招式威力＋攻擊－對方防禦，先做屬性加一半／減半兩項比較（可依次同時符合），各步保留整數，最低1；對方本輪沒有出招時再減半，最低1。迴避則跳過扣HP；命中最多扣剩餘HP。PS1實際扣招式MP。先手以角色速度＋招式速度比較，同值用亂數；達兩倍的差距影響後續出手安排。智力在這段普通公式影響迴避，不直接加入傷害。

原始屬性正規化：Fire8→0、Wind4→1、Nature2→2、Cool1→3，三張光碟已核對。傷害加成表為[3,1,0,2]，抗性表為[1,3,0,0]，索引是受招方的正規化屬性；以招式屬性作比較。這造成不尋常配對，例如Fire招式打Nature會先加一半再減半；攻略保留原碼，不自行改成一般印象的剋制循環。加一半採截向0的一半相加，減半採減去截向0的一半；正值101只受抗性後為51，而非50。

原始迴避門檻索引是max(0,trunc((受招智力−出招智力＋99)/100))，亂數%100低於讀出的門檻即標記迴避。索引0–9的門檻[0,5,5,5,5,10,15,20,25,30]；極端差距901–999會讀索引10的相鄰資料，各版為Fire0、Wind168、CoolNature4。168涵蓋全部0–99值，但不是實機量測勝率。邊界結果明確標為未完成實際全場驗收。

AI執行原始候選整理、招式速度排序、戰術分類／HP分段、MP篩選、選招、雙方普通計算及回合安排。已測所有CPU實有戰術組合，加16組對角戰術；8招混合、MP0／9／30／500、HP比例原碼門檻256／306／307／512／513／727／728／1024、兩組亂數輸入流，共5248個首輪案例。Fire低MP案例以動作0補位，後續版本同類首輪無招式而等待；不把這個首輪結果冒稱整場低MP行為。足夠MP另測144次連續呼叫，包含第二動作快取與高速後續安排。

重要界線：嘗試Wind低MP續回合時，原始指令要求讀位址0x6，超出本次嚴格記憶體模型；未補造該處資料，也未據此宣稱實機會當機。因此後續版本MP耗盡的續回合、回復／動畫時序及整場行為仍待實際驗收，正文已標明。連續呼叫通過的部分只限足夠MP的固定HP／MP背景，不是完整對戰模擬。

公式與IQ邊界共54939項核對；原始傷害限制／命中迴避扣血72項，MP扣減30項；之前三張光碟的戰後能力加成5760項亦整合入正文。網頁試算以1440份原始指令輸出作對照，涵蓋全部119招、三張光碟及四種受招屬性；另檢查輸入界線、手機及離線資源。

執行界線：AI只提供亂數及標準記憶體複製／填值服務，判斷原碼未代換；資源扣減測試略過UI配置／動畫，保留原始HP／MP寫入；沒有新增完整3D演出或對戰保存重開驗收。所有119招／替代動作0的普通數值均涵蓋，異常狀態與特殊演出未逐項實機驗收。Fire記憶碎片10來源仍未找到，沒有改寫為已解明。

### 低MP續回合補核

針對原先模型未涵蓋的位址0x6半字值，沒有假定其實機內容。先核對原碼只保留低10位，並對全部1024值及MP預算0–30執行原始成本比較，共63488項；再以6個比較類別值，配合3組戰術及MP0／9／30，執行兩次／八次原始AI呼叫，共936次。這是帶明確未知輸入的範圍核對，不是填入某個值便當成實機事實。

結果可出現先等待、其後續等或使用後備動作的不同分支，攻略因此只說明首輪及存在後備分支，沒有聲稱後續版本MP耗盡就永遠不攻擊。試算現列119招加基本／後備動作0，各版皆可查看數值；動作0不是可學招式，觸發條件及整場行為另看版本，並不保證玩家可直接指定。實際低位RAM內容、完整3D戰局、MP回復時間與保存重開仍未新增驗收。核對檔：`research/check_ps1_low_mp_continuation.py`、`research/ps1-low-mp-continuation-validation.json`。


### 2026-11-01：受擊反應、後續行動與特殊演出

原版三張光碟完成有範圍的原始程式核對，正文新增「被打到會硬直？會唔會少一次出招？」。受擊完成旗標未設置時，攻擊控制器返回0並繼續等待；完成後兩條反應都返回2（未倒下）或6（倒下）。這證明流程放行條件，不把返回2直接冒稱完成所有下一回合畫面。

長反應計數小於56不完成；56時若HP條busy，反應計數先減1，外層再加1，故停在56。恢復還要看模型動畫狀態／長度；內部計數不能換算成固定畫格或秒。Fire／Wind短反應讀模型+0x1530（0x12DC+0x254）；長反應另讀+0x1788。測試兩處分別填動畫長度20，Cool另填idle長度+0x270；先前研究筆記的相加結果不得混用。

受擊完整後半段以指定模型狀態執行：每版840組，共2520組。保留實際被引用的角色記錄、AI續行模式及其他戰鬥旗標；只省略物件清理服務，Cool資源通道設原碼的停用值，原始整數正弦／查表移動運算保留。另每版32組控制器尾段，共96組，核對未完成／完成、倒下／存活及兩種反應的返回值與計數。

為分開動畫等待與AI行動損失，先由原始AI建立待續狀態，固定HP／MP／速度／比例背景／亂數流，分無受擊、短反應完成、長反應完成三路比較。3組戰術×2組速度×3路×8次×3版本＝432次原始AI呼叫；結果一致，角色記錄及亂數未被受擊後半段改寫。MP固定500且未模擬再次扣血／扣MP，動畫狀態人工提供；這是有控制條件的對照，不是全場實機測試，也不排除HP變化本身影響AI。

特殊演出分類交換／路由1071組：三類每版56／42／21招，單換分類不改普通公式的五項結果；不等於整段動畫對所有遊戲效果都相同。Cool／Nature原始helper0x800DD9B0，在最大HP1–9999的所有四分之一門檻附近共49989組通過。原始caller用已限制到剩餘HP內的傷害選反應bit25；沒有另加暴擊倍率。Fire／Wind已追到的普通設定強制選長反應。
